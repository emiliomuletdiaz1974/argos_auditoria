# Nota de Desviación — ARG-029/030 API GraphQL del inventario y planificador de reexploración

**Fecha:** 2026-09-15 · **Autor:** Aaron Escobar · **Estado:** aprobada
**Aprobación:** Aaron Escobar, 2026-09-15 · **Vía:** asíncrona (refinado de la Fase 03, F03-R)

## 1. Qué dice el documento de fase
**ARG-029 (`api/graphql_app.py`):**
- Autenticación con `argos_auth.fastapi.require_role("auditor_lectura")`.
- `_selector_to_cypher` compone `MATCH (n:{sel.get('label','Column')})` con la etiqueta que manda el cliente.
- `name_like` se usa como expresión regular sin límites.
- El texto pide "paginación obligatoria, profundidad máxima 4 y coste por consulta", pero el código no lo implementa (`LIMIT 200` y `LIMIT 10000` fijos).
- No hay forma de consultar una instantánea.

**ARG-030 (`scheduler/rescan.py`):**
- `RescanPlanner` lanza hijos `"ScanSystem"`, que no se definen, con `uuid.uuid7()` dentro del workflow.
- `score_systems` une `scan_runs` dos veces con `inventory_deltas`.
- El cron se registra con `cron_schedule`.
- "N se autolimita por la carga observada del appliance."

## 2. Con qué choca en la realidad
- **`argos_auth`:** no tiene submódulo `fastapi` (`interfaces-F01.md`). El rol se llama `read_only_auditor` y los cuatro roles del realm pueden leer el inventario.
- **Etiqueta del cliente en la consulta:** interpolarla sin lista blanca permite inyectar Cypher (`Column) DETACH DELETE n //`).
- **`name_like` sin límite:** una expresión regular arbitraria abre la puerta a ReDoS en la base de datos.
- **Sin paginación ni límite de profundidad:** el objetivo de menos de 2 s hasta un millón de nodos (Especificación §3.10) no queda protegido.
- **Instantáneas:** la Fase 5 ejecuta campañas **contra instantáneas** (Plan Director §8.2) y la API no las expone.
- **Workflows de Temporal:** deben ser deterministas. Generar UUID aleatorios en el workflow rompe la reproducción, y `uuid.uuid7` no existe en Python 3.12. Temporal ofrece `workflow.uuid4()`.
- **Doble unión de `scan_runs`:** multiplica filas y falsea `recent_new`.
- **`cron_schedule`:** es el mecanismo antiguo; temporalio ≥ 1.8 ofrece Schedules, que se pueden pausar y consultar.
- **Carga del appliance:** no hay aún métrica observada (llega con ARG-094); el límite queda como configuración.

## 3. Alternativa propuesta
- **API:**
  - `argos_inventory.api.app.create_app(store, validator)`: FastAPI + Strawberry 0.327, ruta `/graphql`, `/health` de la Fase 1 y puerto de desarrollo 8002;
  - dependencia `require_reader`, que valida el Bearer con `JwtValidator` y exige al menos un rol de `argos_auth.ROLES`;
  - `resolveSelector` acepta como etiqueta solo `NODE_LABELS`; `name_like` pasa a coincidencia `STARTS WITH` sin expresión regular, con 100 caracteres como máximo;
  - paginación obligatoria `first` (≤ `MAX_PAGE_SIZE = 500`) y `after` (cursor opaco), y límite de profundidad `MAX_QUERY_DEPTH = 4` con la extensión `QueryDepthLimiter` de Strawberry;
  - consulta `snapshot(id)` sobre `argos.inventory_snapshot_nodes`.
- **Planificador:**
  - `ScanSystem` se define como workflow hijo con las actividades `run_scan(system_id, run_id)` (sondas del escáner de descubrimiento, `scan_run` y `scan_completed`) y `compute_run_deltas`;
  - `run_id` con `workflow.uuid4()`;
  - `score_systems` reescrita con subconsultas por sistema;
  - programación con Temporal Schedules (`inventory-rescan-hourly`);
  - `MAX_PARALLEL` configurable, y se respeta `LoadBudget.in_window()` antes de lanzar.

## 4. Efecto sobre el contrato
- **Interfaces exportadas de la fase:** [x] cambia.
  - `node` y `resolveSelector` añaden `first` y `after`.
  - Se **añade** `snapshot(id)`.
  - `name_like` pasa a prefijo.
  - El rol mínimo es cualquier rol del realm.
  - `RescanPlanner` y `ScanSystem` se conservan con esos nombres.
- **Principios innegociables (§7.2):** [x] ninguno afectado. La API es de solo lectura, sin mutaciones, y el planificador solo ejecuta sondas de los conectores de solo lectura.
- **Estimación de la fase:** [x] +1 día (paginación, límite de profundidad y `ScanSystem`).

## 5. Alternativas descartadas
- **Expresión regular con tiempo límite de sentencia:** protege la base de datos pero no la experiencia, y complica el plan de consulta.
- **API REST en lugar de GraphQL:** el documento y la consola (Fase 8) esperan GraphQL.
- **Seguir con `cron_schedule`:** funciona, pero no se puede pausar ni consultar desde la consola.
