# Nota de Desviación — ARG-073, la consola deja de servirse desde la API

**Fecha:** 2026-09-29 · **Autor:** Aaron Escobar · **Estado:** aprobada (decisión directa del usuario, 2026-09-29)

## 1. Qué dice el documento de fase
- El documento de la Fase 08 construye el frontend en React y lo sirve como estáticos desde el propio appliance, sin CDN.
- ADR-0013, punto 5: «La consola se sirve desde la API única. `npm run build` deja los estáticos en `console/dist`; la imagen de `argos-api` los copia y FastAPI los sirve en `/`. Un solo contenedor, un solo origen».
- ADR-0013, consecuencias: `make check` incorpora `console-lint`, `console-test` y la comprobación de los tipos generados, y el CI ejecuta el guion de Playwright.

## 2. Con qué choca en la realidad
El front end de ARGOS lo construye otro equipo, como aplicación aparte y desde otro origen. La consola de la Fase 08 ya no es la interfaz que se va a entregar, pero seguía dentro de la imagen de la API, en `make check` y en el CI. Eso tenía dos costes: mantenía dos cadenas de herramientas para una interfaz que no se usará, y servía una interfaz que no es la del producto.

## 3. Alternativa aplicada
- La API deja de construir y de servir la consola: fuera la etapa `node` del `Dockerfile` y `_serve_console` de `argos_api.app`. Todo lo que no es una ruta de la API responde `404` en `application/problem+json`, con las mismas cabeceras de seguridad (SEC-046).
- `make check`, el CI y `make sbom` dejan de tratar la consola. Las excepciones de `vex.yaml` para `vitest` (SEC-057) se retiran porque no queda ningún SBOM de la consola al que aplicarlas.
- El código de la consola **se queda en `console/`**, con sus objetivos `console-*` del Makefile para ejecutarlos a mano. Sirve de referencia: sesión PKCE, renovación con un solo reintento y vistas que ya aplican las reglas del servidor.
- El equipo del front recibe `docs/tecnica/guias/integracion-frontend.md`: endpoints, roles, sesión, errores y flujos. `tools/docs_pack.py` admite un tipo de documento `guide` para poder entregarla empaquetada.

## 4. Efecto sobre el contrato
- Interfaces exportadas de la fase: la v1 no cambia (el contrato `openapi.json` es el mismo). Cambia lo que responde `/`: antes la página de la consola, ahora `404`.
- Principios innegociables (§7.2): ninguno afectado. La seguridad de la API no cambia en este paso.
- **Pliego P-18** (consola web en castellano con el ciclo completo): pasa a cumplirlo el front del otro equipo. La guía le traslada esos requisitos, y la accesibilidad EN 301 549.
- **Queda abierto y bloquea la integración:** la API todavía no admite un front de otro origen. El middleware `_same_origin` rechaza con `403` todo `POST` de otro origen, no hay CORS, y la cookie de refresco es `SameSite=Strict`. Se trata en una tarea aparte con sus tests.

## 5. Alternativas descartadas
- **Retirada completa (borrar `console/`):** descartada por el usuario. El código sigue siendo útil como referencia y queda en el historial de git en cualquier caso.
- **Mantener la consola servida junto al front nuevo:** dos interfaces para lo mismo, y una de ellas sin dueño.
- **Resolver CORS en este mismo cambio:** cambia la seguridad de la API (SEC-058, cookies de sesión). Merece su propia tarea, con los tests de la batería de accesos.

## 6. Actualización del documento de fase
ADR-0013 queda aceptado salvo el punto 5 y las consecuencias sobre `make check` y el CI, sustituidos por esta nota. Anotar en ARG-073 la referencia a esta nota.
