## 1. Qué dice el documento de fase
`connectors/sql/argos_sql/generic.py`:
- Construye las consultas con f-strings: `SELECT COUNT(*) FROM {spec.target} WHERE {where}` y `SELECT {cols} FROM {target} LIMIT {k}`.
- `SESSION_RO` aplica por dialecto `ALTER SESSION SET READ ONLY` (Oracle) y `SET LOCK_TIMEOUT` (SQL Server), en el evento `connect` y sin commit.
- La minimización es `sha256(str(v))[:16]`.

En `postgres.py`, la comprobación `encryption_at_rest` devuelve `data_directory` y la clave `nota`. En `oracle_mssql.py`, `open()` ejecuta `DDL_LOCK_TIMEOUT` y `SET TRANSACTION ISOLATION LEVEL SNAPSHOT` sobre una sola conexión.

## 2. Con qué choca en la realidad
- **Inyección:** interpolar `target`, `columns` y `where` permite inyectar SQL, por ejemplo `patients; DROP TABLE x`.
- **`LIMIT` no es portable:** SQL Server usa `TOP` y Oracle, `FETCH FIRST`. La prueba con SQLAlchemy 2.0.53 del 2026-09-14 confirma la compilación correcta por dialecto: `TOP 100`, `FETCH FIRST 100 ROWS ONLY` y `LIMIT :param_1`.
- **Solo lectura en Oracle:** `ALTER SESSION SET READ ONLY` no existe. La forma válida es `SET TRANSACTION READ ONLY`, que se aplica a cada transacción.
- **La sesión de solo lectura se pierde en PostgreSQL:** psycopg abre una transacción implícita al ejecutar en el evento `connect`, y `SET` es transaccional. Al devolverse la conexión al pool se hace rollback y se pierde la sesión de solo lectura.
- **Ajustes en una sola conexión:** lo que se ejecuta en `open()` solo afecta a una conexión del pool.
- **`SNAPSHOT` falla** si la base no tiene `ALLOW_SNAPSHOT_ISOLATION`.
- **MariaDB** usa `max_statement_time` en segundos; `max_execution_time` es de MySQL.
- **Hash sin clave:** un hash truncado de datos personales de baja entropía (DNI, fechas) se invierte con un diccionario.
- **`data_directory`** expone rutas del servidor del cliente sin aportar evidencia de cifrado.
- **`DDL_LOCK_TIMEOUT`** no afecta a las lecturas.

## 3. Alternativa propuesta
- **Construcción de consultas:** se construyen con SQLAlchemy Core (`table()`, `column()`, `select()`) sobre identificadores validados y se compilan para el dialecto real con parámetros con nombre.
- **Texto único:** el texto compilado es el que se registra en el diario, se valida con sqlglot (ARG-011) y se ejecuta.
- **Ajustes de sesión:** en el evento `connect`, para cada conexión del pool, seguidos de `commit()`:
  - **PostgreSQL:** `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY`, `statement_timeout` y `lock_timeout`.
  - **MySQL y MariaDB:** `SESSION TRANSACTION READ ONLY` y el timeout propio de cada motor, detectado por `VERSION()`.
  - **SQL Server:** `LOCK_TIMEOUT`, con la cuenta `db_datareader` como garantía.
  - **SQLite (tests):** `PRAGMA query_only = ON`.
- **Oracle:** `SET TRANSACTION READ ONLY` en el evento `begin` y `call_timeout` en la conexión, con driver `oracledb` en modo thin.
- **Aislamiento:** opcional por configuración (`isolation_level`), para no fallar en bases sin snapshot.
- **Comprobaciones con nombre (`CONFIG_CHECKS`):** llevan SQL literal, que se registra y se valida igual.
  - PostgreSQL: `privileges`, `encryption_at_rest` (con `ssl`, `password_encryption` y `data_checksums`) y `replica_status`.
  - Oracle: `audit_status`, `generic_accounts` y `privileged_grants`.
  - SQL Server: `audit_status`, `generic_accounts` y `privileged_grants`.
- **Minimización:** HMAC con clave por sistema (`ValueHasher`, ARG-011); `sample` devuelve `cell_digests`.
- **Idioma:** claves de resultado en inglés (`note`).
