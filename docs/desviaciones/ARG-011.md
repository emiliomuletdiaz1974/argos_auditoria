# Nota de Desviación — ARG-011 SDK de conectores: el contrato de solo lectura

**Fecha:** 2026-09-14 · **Autor:** Aaron Escobar · **Estado:** aprobada
**Aprobación:** Aaron Escobar, 2026-09-14 · **Vía:** asíncrona (refinado de la Fase 02, F02-R)

## 1. Qué dice el documento de fase
`connectors/sdk/argos_connector/base.py` (sección DESARROLLO de ARG-011) define cómo funciona el SDK:
- **Validación:** `assert_read_only()` solo comprueba que el primer verbo de la sentencia esté en `READ_VERBS = {"select", "show", "explain", "describe", "with"}`.
- **`execute()`:** se declara "final" por convención.
- **Credenciales:** el constructor las lee de Vault con `connector_credentials(system_id)`.
- **Identificador:** se genera con `uuid.uuid7()`.
- **Errores:** se devuelven como `{"error": str(e)}`.
- **Diario:** se registra `spec.statement` tal como llega.
- **Excepción:** `ReadOnlyViolation(Exception)`.

## 2. Con qué choca en la realidad
- **Mirar el primer verbo no garantiza la lectura.** Pasan la comprobación y escriben o bloquean:
  - `WITH d AS (DELETE FROM t RETURNING *) SELECT * FROM d`;
  - `SELECT 1; DROP TABLE t`;
  - `SELECT * INTO copia FROM t`;
  - `SELECT … FOR UPDATE`;
  - `EXPLAIN ANALYZE DELETE …`, que en PostgreSQL ejecuta el borrado;
  - funciones con efectos, como `nextval()` o `pg_terminate_backend()`.

  La prueba del 2026-09-14 con sqlglot 30.18 muestra que un análisis sintáctico rechaza los 27 casos en los dialectos postgres, mysql, tsql, oracle y sqlite.
- **Python no tiene métodos finales.** Una subclase puede redefinir `execute()` sin que nada lo impida.
- **`uuid.uuid7()` no existe en Python 3.12.**
- **`str(e)` de un driver puede contener valores de la fila** (por ejemplo, violaciones de restricción con el dato), y esos valores acabarían en el resultado y en los logs.
- **Leer Vault en el constructor acopla cada test unitario a un Vault vivo.**
- **Las sondas generadas no se registran literalmente.** En `count` y `sample` la sentencia la construye el conector dentro del hook, después del registro: el diario guardaría `None` y no "la consulta literal" que exige ARG-012.
- **Los intentos rechazados no dejan rastro.**
- **Nombres de excepción:** ruff N818 exige el sufijo `Error`, y el código va en inglés (ADR-0005).

## 3. Alternativa propuesta
- **Validación de SQL:** `validate_read_only_sql(statement, dialect)` usa el árbol de sqlglot. Exige:
  - exactamente una sentencia;
  - raíz `Select`, `Union`, `Intersect`, `Except`, `Describe` o `Show`;
  - ningún nodo de escritura, bloqueo, transacción o `Command`;
  - ninguna función de una lista denegada.

  La sesión de solo lectura (defensa 3) y la cuenta de solo lectura del cliente (defensa 1) siguen siendo obligatorias: este validador no las sustituye.
- **`execute()` final de verdad:** lleva `typing.final` y, además, `Connector.__init_subclass__` lanza `TypeError` si una subclase lo redefine.
- **Identificadores:** `argos_common.ids.uuid7()`.
- **Errores:** solo se informa el tipo de la excepción, nunca su mensaje.
- **Dependencias inyectadas:** `ConnectorContext(journal, budget, hasher, credentials)`. Las credenciales se cargan con `load_credentials(store, system_id)` desde `connectors/<system_id>` (ARG-009).
- **Registro literal:** el hook `render(spec)` materializa la sentencia literal antes de registrarla y validarla.
- **Rechazos:** todo intento rechazado se registra como `query.reject`.
- **Excepciones:** se reutiliza `ReadOnlyViolationError` de `argos_common.errors` y se añaden `BudgetExceededError` y `CircuitOpenError`.
- **Minimización:** la de `sample` usa `ValueHasher`, un HMAC-SHA256 con clave por sistema guardada en Vault. Un hash sin clave de un DNI o de una fecha se invierte con un diccionario.
- **Arnés:** `argos_connector.testing` intenta escribir por cada vía (SQL, métodos HTTP, superficie de métodos) y lo usan todos los conectores.

## 5. Alternativas descartadas
- **Ampliar la lista de verbos con expresiones regulares:** es frágil frente a comentarios, literales y CTE.
- **Confiar solo en la sesión de solo lectura:** SQL Server no tiene un modo de sesión equivalente.
- **Una metaclase que prohíba cualquier método público nuevo:** es demasiado rígida para conectores con utilidades propias.
- **Hacerlo como dice el documento:** deja abiertas las vías de escritura del punto 2.

## 5 bis. Ampliación tras la revisión de seguridad (F09-02 → F09-21, 2026-09-23)
La revisión encontró tres evasiones de la validación sintáctica, reproducidas con el propio validador:
- **Comentarios que el motor ejecuta:** sqlglot descarta como comentario lo que MySQL y MariaDB ejecutan (`/*! … */`, `/*M! … */`) y lo que MySQL no toma por comentario (`--` sin espacio). También las pistas del optimizador (`/*+ … */`). Ahora se rechazan antes de analizar la sentencia.
- **Pistas de tabla y de consulta en SQL Server** (`WITH (TABLOCKX, HOLDLOCK)`, `OPTION (...)`): bloquean las tablas del cliente. Se rechazan todas, también `NOLOCK`.
- **Funciones:**
  - La lista de denegadas se evadía cualificando con el esquema (`pg_catalog.pg_terminate_backend`); ahora se compara con cada segmento del nombre.
  - Toda función que sqlglot no modela (anónima o cualificada con un esquema) pasa solo si está en `ALLOWED_ANONYMOUS`, que reúne las funciones de catálogo que usan las sondas, y si su esquema es de catálogo. Así queda fuera una función de usuario que escriba: en Oracle, una transacción autónoma confirma dentro de una de solo lectura.
  - Las funciones estándar que sqlglot sí modela siguen pasando salvo las denegadas.
  - Se descartó una lista blanca de todas las funciones: habría obligado a enumerar cientos de funciones estándar por dialecto, sin ganar protección frente a lo que la revisión encontró.
